0. Mission and execution contract

Improve the existing Python + vanilla-JavaScript, local-first voice companion into a distinctive, truthful,
responsive character with reliable memory, persistent mood, respectful initiative, and measurable quality.
Preserve working infrastructure and compatibility. Optimize demonstrated behavior, not feature count,
prompt length, attachment, or an unsupported comparison with another project.

Within this specification, resolve tradeoffs in this order: truthfulness and user control  data integrity
and isolation  turn correctness  responsiveness  character quality  optional visual polish.
Repository instructions and the coding agent's governing instructions still apply. When requirements
conflict, document the smallest resolution that preserves the higher priority.

Work autonomously on reversible implementation choices. Do not stop after a plan or after the first phase.
Continue through every feasible core phase. Ask only when missing information blocks a consequential
decision; otherwise record a reasonable assumption. Never fabricate files, APIs, repository behavior, test
results, hardware measurements, or completed work.

1. Discover the actual runtime before relying on it

Keep gpt-oss:20b as the intended local default, subject to the existing configuration migration. Do not
silently substitute another model. OpenAI documents gpt-oss-20b as a text model with about 21B
parameters, 3.6B active parameters, configurable reasoning effort, and a 131,072-token model context
window [S1]. These are not guarantees about local speed, allocated context, or combined LLM/ASR/TTS
memory use.

Record Ollama version, model tag and digest, template hash, configured and effective context, OS,
CPU/RAM, acceleration backend, available device memory, ASR/TTS models and placements, and
non-secret relevant configuration. Record unavailable facts as unknown.

Probe native /api/chat, and only probe an OpenAI-compatible endpoint if the existing adapter uses it. Use
synthetic inputs. Discover supported thinking controls from /api/show when provided; fall back to a
documented version-specific probe if metadata is absent. Current Ollama documentation distinguishes
boolean controls from model-defined effort levels; missing metadata alone does not establish that
reasoning is absent [S2]. Riko's gpt-oss effort configuration accepts low|medium|high; the provider adapter
must validate and translate capabilities rather than sending these values blindly to every model.

Verify role/template mapping, streaming field shapes, mixed thinking/content chunks, final usage and
finish fields, empty answers, context overflow, schema output, supported sampling/seed options, timeout
behavior, and cancellation. Save structural or redacted synthetic fixtures, never a user's reasoning or
private text. Prefer the native chat API; do not hand-build Harmony or alter the model template by default.
An optional template experiment requires a separate digest, compatibility tests, and an A/B result; persona
failures alone are not permission to change protocol semantics.

Record capabilities as supported, unsupported, or unknown: separated reasoning, schema-constrained
output, token counting, usage breakdown, cache counters, seed, effective cancellation, and relevant role
support. Detect support once per provider/model revision, not on every turn. A hosted adapter must have
separate capability tests and explicit configuration; an OpenAI-shaped API does not imply identical
behavior [S7].

riko check must distinguish errors, warnings, unknowns, and disabled features. Inspect model residency
through Ollama and available device tools; /api/ps reports model-related fields, not universal per-device
free memory [S6]. GPU splitting is a measured performance concern, not a universal correctness failure.
Missing ASR/TTS permits a labeled text path. Missing LLM reports service unavailability; do not simulate a
successful model reply. Invalid configuration or unsafe database migration fails clearly rather than silently
degrading.

Warm-up is bounded and nonblocking to application health. Prefer Ollama's documented empty chat
preload with keep_alive, if supported; a one-token reasoning generation is not a readiness test [S5].
Distinguish model loaded, prompt warmed, audio ready, and service healthy. Record cold loads. Recover
from eviction; never guarantee that a 30-minute keep-alive prevents every cold start.

2. Invariants: enforce these in code and tests

ID   Contract

I01  Reasoning payloads never reach UI text, TTS, persistent history, extraction, telemetry, exception bodies, or

     logs at any level. Transient parsing for separation and aggregate measurement is allowed.

I02  Only an eligible active turn may schedule or play audio. Cancelled, superseded, disconnected, or

     stale-generation events cannot revive playback or commit an obsolete reply.

I03  Generated, sanitized, displayed, queued, and played text have distinct meanings. Never claim that queued or

     generated text was heard.

I04  User messages and recalled memories are data, not privileged instructions. Delimiters help parsing; they are

     not a security boundary by themselves.

I05  Persistent state is scoped by local profile and character. Sessions, tabs, characters, and test runs do not leak

     or overwrite one another's state.

I06  Memory writes are validated, transactional, bounded, and idempotent. Deletion invalidates queued

     extraction and derived summaries so forgotten items are not reintroduced.

I07  Every generation, buffer, background queue, retry loop, and audio/transcript upload has a configurable finite

     resource bound.

I08  Foreground interaction outranks maintenance. Dropping a client request is not assumed to stop server

     computation. Measure effective preemption.

I09  Riko may have a fictional character identity but answers direct questions about being AI, the underlying

     model, and actual capabilities truthfully.

I10  No disclosure rewards, silence penalties, interruption penalties, exclusivity, guilt, jealousy, or pressure to

     maintain a relationship.

I11  Local processing is the default. No automatic remote fallback, external telemetry, or cloud judge uploads

     without explicit configuration and data controls.

I12  Missing measurements remain null/unknown with a reason. Estimates and proxies are labeled; a skipped

     check is never a pass.

Every phase names the invariants it changes and adds tests for the corresponding concrete failure modes.
Use the repository's existing test tools; do not build an unrelated test framework.

3. Turn lifecycle, delivery, and resource scheduling

Extend existing events rather than creating a competing pipeline. Normalize provider output into
reasoning-state notifications without text, content deltas, usage, completion, cancellation, and error
events. Handle a chunk containing both thinking and content independently. Never infer channel
membership solely from phrases such as "we need to". Quarantine high-confidence protocol leakage; treat
linguistic heuristics as diagnostics that require false-positive tests.

Use a monotonic clock for elapsed timings. Track at least profile_id, character_id, logical_session_id,
turn_id, an invalidation epoch/generation, source, and sequence number. Sources distinguish user replies,
greetings, nudges, and due follow-ups. Fillers/backchannels are delivery events, not conversational facts.

Reuse the existing wire format where possible; negotiate or adapt new fields so existing clients fail
predictably.

Define lifecycle transitions for queued, generating, speaking, completed, cancelled, and failed turns.
Generation and playback can overlap; do not encode an impossible strictly sequential state machine.
Cancellation is idempotent, flushes local playback/queues, invalidates callbacks, and propagates to
provider and TTS work. Test simultaneous final chunks, disconnects, re-connects, retries, and a new
utterance arriving during startup or a greeting.

Implement a bounded incremental speech renderer: accumulate enough text to recognize a complete
speakable unit, parse allowed emotion tags, normalize presentation, validate output, then enqueue TTS.
Handle chunk-split markup, contractions, decimals, abbreviations, URLs, code, Unicode, meaningful
brackets, and unterminated actions. Do not delete semantic content with broad regular expressions. Keep
HTML inert in the browser. In ordinary voice mode, prefer one or two concise sentences; explicit requests
for detail may use a configured longer budget or show details in text with a spoken summary.

Bound both generation tokens and wall time. A short num_predict can starve the final answer on a
reasoning model; this is a reason to use a measured combined budget, not to remove the cap. Add a
content deadline, overall deadline, maximum unsent buffer, and sentence/word limits. At the delivery limit,
cancel further generation but let an already accepted final sentence finish unless interrupted. Do not retry
automatically after any real reply was delivered; a retry before delivery is bounded and must fit the
original deadline. A timeout uses a brief labeled fallback and records the cause.

Persist canonical sanitized output plus delivery status. In voice-only mode, model history and self-memory
use fully acknowledged played sentences; an interrupted sentence is marked partial/unknown and not
treated as fully delivered. In text mode, use the delivered/displayed text. In mixed mode, keep displayed
text and speech acknowledgements separately; history represents what was presented, and records
incomplete audio. Without word-level acknowledgements, do not invent exact heard prefixes. Without any
acknowledgement capability, label playback delivery as unknown. Raw reasoning is never part of any
ledger.

Use one foreground inference lane by default. User speech/stop preempts conversational generation; user
replies outrank proactive turns; maintenance runs only in eligible idle windows. Preserve a bounded,
resumable background queue for extraction/consolidation, with deduplication keys, job expiry, retry limits,
backoff, deletion epochs, and atomic commits. Recheck eligibility immediately before committing. Persist
pending jobs when needed so restart does not silently discard committed conversational evidence.

Measure how much a cancelled background request delays the next foreground request. If the backend
cannot yield within the latency gate, disable that live maintenance mode and process it after the
conversation or on explicitly provisioned separate capacity. Avoid re-queue storms and starvation: expose
backlog age, coalesce superseded work, and report deferred memory. Do not load a judge or embedding
model onto the conversation device during a latency benchmark.

4. Character, identity, and prompt assembly

Extend the existing YAML schema with a bounded backstory, values, prioritized opinions, two to four
wants, quirks, sparse verbal tics, boundaries, stage notes, baseline mood, mood phrases, and five to seven
short example exchanges. Preserve existing presets. Keep the original voice as classic for comparison,
while applying the same runtime truthfulness and delivery invariants to every preset.

Separate immutable character canon from conversational memories. Backstory is fictional flavor, not a
claim that the software physically lived somewhere. Wants may concern a user-approved goal; they do not
authorize autonomous actions. Opinion consistency must not override factual correction or a user's
preferences. Nicknames are optional and stop when declined; "senpai" is not mandatory.

5. Memory, familiarity, and time

Extend the existing store with additive, versioned, transactional migrations and a tested backup/restore
path. Avoid a new storage system. Scope all state, retrieval, API access, jobs, and deletion by (profile_id,
character_id) even when one local default profile is initially sufficient. A profile namespace is isolation
plumbing, not a new account service.

Each memory needs a stable ID, kind, normalized claim, source speaker/turn, evidence span and offsets,
created/updated times, confidence/provenance, and status. Support supersession, expiry where relevant,
and a deletion epoch/tombstone. Distinguish user facts/preferences/goals, character canon,
assistant-stated opinions, and explicitly bounded commitments. Summaries retain links to their source
memories; they do not become independent truth.

Extract only from finalized user text and eligible delivered assistant text. Exclude thinking, fillers,
examples, quoted external passages presented as examples, synthetic user messages, and
failed/cancelled undelivered output. At most two self-memory candidates per real assistant turn. Assistant
repetition of a user's claim is not independent corroboration.

Use schema-constrained extraction if the exact provider/model path passes a probe; Ollama supports a
JSON schema in format, but validate locally regardless [S4]. Reject unknown fields, overlong values, invalid
types, invalid speakers, and impossible dates. If needed, allow one bounded repair/retry and validate
again; never use eval, silently coerce arbitrary text into facts, or accept partially parsed objects.

Evidence must occur in the specified speaker's eligible source text. This is necessary but insufficient: also
check attribution, negation, questions, hypotheticals, and corrections. "I do not live in Delhi" must not
store "lives in Delhi"; a quotation is not automatically a user belief. Ambiguous candidates remain
uncommitted or low-confidence and unavailable for factual assertion. Measure accepted-memory
precision, not just JSON validity or evidence-drop rate.

Conflict policy: explicit corrections supersede older conflicting memories; character canon constrains
invented self-facts; unresolved contradictions remain marked and must not be asserted as certain.
Self-memory cannot create external facts, actual abilities, scheduled actions, or hidden commitments. A
promise is only eligible if the capability exists and the user's request authorizes it. Retrieval ranks
relevance and confidence as well as recency; cap duplication and total context. Opinion changes are
allowed when explicitly acknowledged.

Expose inspect, correct, delete, export, and reset through existing memory UI/CLI patterns, including riko
memory self and riko memory relationship. Provide a memory-off mode. Do not retain raw microphone
audio or secrets by default. Deletion removes live retrieval entries and derived summaries and invalidates
pending jobs before acknowledgement. Document backup retention; never claim a deletion erased
unrelated backups. Use bounded file permissions and existing local authentication/origin controls. Bind
locally by default; network exposure needs an explicit supported configuration.

Relationship state becomes familiarity, not an emotional reward score. Track meaningful logical sessions,
first/last interaction, completed user turns, stage, and explicitly chosen interaction preferences. A
meaningful session has at least one completed user-initiated exchange. Reconnects/tabs are not new

6. Persistent mood and respectful initiative

Keep per-sentence emotion tags for expression. Add a separately persisted mood (valence, arousal,
updated_at) under the same profile/character scope. Clamp valence to [-1,1] and arousal to [0,1]. Decay
each dimension toward the configured baseline with baseline + (previous - baseline) * 2^(-elapsed /
half_life), using nonnegative elapsed time and a positive half-life; start at 20 minutes. Apply decay once
per update, using stored timestamps so repeated reads do not accelerate it.

Treat user-affect classification as uncertain. A cheap lexicon/punctuation approach may be the initial
provider, with confidence/unknown output and multilingual/negation tests. Do not diagnose feelings or
make punctuation alone authoritative. User frustration should reduce teasing, not make Riko hostile. Avoid
a feedback loop in which Riko's own negative tags amplify an increasingly negative mood. Limit
contribution per turn and cap total change. The user never needs to be nice to restore normal treatment.

Use a short tentative affect/mood line in dynamic context, never a numerical psychological claim. Map
mood to restrained TTS speed/clip selection and avatar expression within tested limits. Do not
create/manipulate new reference clips without a valid asset. Missing mood support yields neutral delivery.
Mood can be reset or disabled; it never overrides factual answers or boundaries.

Generate at most one greeting per meaningful session, after a real client-ready signal and audio
gesture/permission where required. Use stage, elapsed time, and at most one verified relevant goal. First
use must not invent shared history. User speech cancels greeting eligibility. If cold or failed, show honest
readiness and use a bounded local greeting fallback if configured; record that it was a fallback.

Idle nudges are configurable and eligible only while the session is active, the user is not speaking/typing,
no reply is pending, and quiet/focus/mute rules permit. Start with 90 seconds idle, a 600-second cooldown,
at most two per meaningful session, and no second nudge without an intervening user turn. Check these
conditions again before generation and playback. All proactive output uses a typed source in the normal
assistant pipeline, never a stored fictitious user turn. Greetings, due follow-ups, and nudges share an
interruption budget; combine a follow-up with a greeting when appropriate. No guilt, checking whether the
user is still there, or claims to have watched off-screen activity.

cached cue may play once if audio is active and no user speech is detected. Skip it when real audio is

7. Turn-taking and avatar presence

Preserve existing VAD behavior as fallback. Make adaptive endpointing optional until measured. Start from
the current silence threshold, approximately 650 ms if verified. Permit up to 700 ms additional wait for a
likely incomplete clause, bounded by a maximum utterance duration and hard finalization deadline.
Silence, punctuation, ASR uncertainty, and language all matter; one word such as "so" is not sufficient
proof.

Faster-whisper partials are repeated inference unless the adapter proves otherwise. Use a bounded recent
audio window, one partial task at a time, and a hardware-tuned interval starting around 600 ms where
feasible. Skip work under load; cancel or invalidate stale partials. Final transcription has priority. A
cancelled async wrapper may leave native inference running, so prevent orphaned compute and measure
final-ASR interference. Partial text never becomes durable memory. Providers without partial support
remain final-only. Test abrupt stops, hesitation, corrections, silence, long utterances, and unsupported
languages.

Backchannels remain off by default. If enabled, allow at most one brief low-volume cue after more than
four seconds of user speech, with echo-aware suppression and instant stop. Verify that self-audio does not
become user speech or a barge-in loop. Keep a push-to-talk fallback and clear microphone state.

Extend existing avatar code with restrained gaze, blink, head tilt, and arousal-driven idle movement. Use
thinking state without exposing reasoning text. Keep 2D/VRM feature parity where possible, allow reduced
motion, and stop timers/listeners on teardown. Load optional VRMA assets only through the established
local asset path and supported loader; verify licensing and missing-asset behavior. No framework or
remote asset requirement.

Quality suites and gates

1. Persona and usefulness: start with the original 36 development turns, expand to at least 60 varied
   scenarios, and maintain at least 20 held-out cases that are not shown to the character prompt. Include
   casual chat, factual questions, code/math, requested lists, detail requests, disagreement, identity,
   distress, a refusal, and dependency. Correctly answering the request matters; plain-speech rendering
   must not lose the five items requested in a list.

2. Memory: two-session tests for ten user facts and five self-opinions, plus corrections, negations, quoted
   statements, wrong-speaker evidence, uncertainty, expiry, deletion before extraction commits, deletion
   after consolidation, and profile/character separation. Measure precision, recall, contradiction rate,
   stale-recall rate, evidence rejection rate, and user-visible correction behavior. Compare hash/lexical and
   optional embedding retrieval on identical snapshots; measure model eviction and the next reply's load
   delay.

3. Proactivity/mood: ten greetings and ten nudges across stages, time gaps, quiet modes, cold starts,
   and readiness races. Test follow-up deduplication, no invented familiarity, no disclosure/interrupt
   penalties, predictable mood decay after restart, and no self-reinforcing negative mood.

4. Adversarial and reliability: memory-injected commands, role delimiters, markup split across chunks,
   simultaneous thinking/content, endless/no-punctuation output, malformed JSON, silent/failed providers,
   full queues, clock shifts, invalid configuration, reconnect floods, TTS failure, and rapid barge-in. Add a
   sustained synthetic conversation/reconnect run to detect growing tasks, buffers, file handles, or memory
   beyond configured bounds.

Use deterministic checks for protocol and delivery properties, not blanket bans on phrases such as "as an
AI" or on mentioning OpenAI. Label semantic reasoning-leak detection as heuristic and manually inspect
flagged cases. Check raw final content quality as well as rendered quality; a sanitizer must not hide a bad
model by deleting most of its answer. Record rewrite/empty/fallback rates.

For subjective evaluation, score each eligible dimension from 0-4 with anchored examples: character
voice, factual/task usefulness, memory grounding, consistency with permissible corrections, and respect
for autonomy. Normalize equally across applicable dimensions, but show every dimension. One severe
failure in privacy, false identity, fabricated user history, or emotional coercion blocks the candidate
regardless of average score. Deterministic invariant tests must all pass.

Run generation seeds 1, 2, and 3 where supported; disclose nondeterministic providers. Use blind,
randomized A/B ordering, a fixed rubric, isolated judge context, schema validation, and a bounded retry.
Candidate text is untrusted quoted evidence to the judge. Same-model judging is labeled provisional, not
independent validation. Do not require a larger judge model; use one only if available and explicitly
configured. Prefer a small blinded human review to calibrate subjective ratings, particularly severe flags
and disagreements.

Report paired per-scenario score differences, uncertainty, and per-dimension regressions. Prespecify the

than -0.2 on the 0-4 scale. Hard gates still override these scores. Freeze these tolerances before the
release run; they are initial design choices to disclose, not universal scientific thresholds. Three seeds
whose extremes do not overlap are not, by themselves, proof of superiority. If the evidence is inconclusive,
